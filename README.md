# GameDev Hub — 第一阶段开发任务

> 当前已按沟通后的轻量版需求实现：软件卡片、官方入口、文档、说明、分类和搜索。没有个人状态与环境预设。下面保留最初的完整需求作为记录。
>
> 日常维护请看 [JSON 配置说明](CONFIG.md)，发布请看 [GitHub Pages 发布步骤](DEPLOY.md)，直接打开 `preview.html` 可查看静态预览。

## 一、项目目标

开发一个名为 GameDev Hub 的个人游戏开发工具网站。

网站用于集中管理游戏开发常用软件、官方下载地址、官方文档、安装说明、免费替代品和个人开发环境清单。

我主要从事 Unity 游戏开发，希望在更换电脑、重装系统或创建新项目时，可以快速找到并安装所需的软件。

我不熟悉网站开发，请你负责具体实现，同时保证代码结构清晰、易于维护，方便后续继续扩展。

## 二、技术要求

- 使用 React + TypeScript + Vite。
- 使用 npm 管理依赖。
- 第一版必须是纯静态网站，不需要后端、数据库、用户登录或服务器。
- 软件资料使用独立的 JSON 或 TypeScript 数据文件维护，不要将所有软件信息硬编码在页面组件里。
- 个人收藏、已安装状态、个人备注和环境清单优先保存在 localStorage。
- 支持导出和导入 JSON 格式的个人数据。
- 使用 GitHub Pages 部署，配置 GitHub Actions 自动构建发布。
- 正确处理 Vite 的 base 路径，保证部署到仓库子路径后资源和页面仍能正常访问。
- 适配 Windows 桌面浏览器，同时兼容手机浏览器。
- 全部用户界面使用简体中文。

## 三、网站页面

### 1. 首页

包含：

- 网站名称和简短介绍。
- 全局搜索框。
- 软件分类入口。
- 常用软件。
- 最近使用的软件。
- 开发环境预设入口。
- 图片处理工作台的预留入口。

### 2. 软件库

至少包含以下分类：

- 游戏开发与引擎。
- 版本控制与代码工具。
- 图片、UI 与美术。
- 音频与视频。
- 通用效率工具。

支持：

- 按软件名称和关键词搜索。
- 按分类筛选。
- 按授权类型筛选。
- 收藏软件。
- 标记已安装。
- 查看软件详情。

### 3. 软件详情

每款软件包含：

- 软件名称、图标或统一占位图。
- 软件用途。
- 分类。
- 支持的操作系统。
- 授权类型：免费、开源、商业、免费增值等。
- 官方下载地址。
- 官方文档地址。
- 安装步骤。
- 前置依赖。
- 个人使用备注。
- 相关软件。
- 免费替代品。

外部链接必须使用明确的链接按钮，并在新标签页打开。

不要编造下载地址、版本号、授权信息或软件功能。无法确认的信息标记为待核实。

### 4. 开发环境预设

预置：

- Unity 开发环境。
- 游戏美术环境。
- 音视频工具环境。

用户可以勾选软件、标记安装状态、保存自己的预设，并导出环境清单。

第一版不需要自动安装软件，只提供官方入口、安装说明和环境清单导出功能。

### 5. 设置页面

支持：

- 导出个人数据。
- 导入个人数据。
- 清空本地数据前二次确认。
- 显示数据版本，便于后续升级。

## 五、代码组织

请采用清晰的模块化结构，例如：

- src/components：通用 UI 组件。
- src/pages：页面。
- src/data：软件目录、分类和环境预设。
- src/types：TypeScript 类型定义。
- src/services：搜索、收藏、本地存储、数据导入导出。
- src/styles：全局样式与主题。
- public：静态图标和其他公开资源。

可以根据实际需要调整目录，但不要为了形式而过度拆分类和组件。

## 六、设计要求

采用现代、简洁的开发者工具网站风格。

- 清晰的导航栏与分类侧栏。
- 软件卡片显示名称、用途、授权类型。
- 软件详情信息层次清楚。
- 搜索与筛选操作直观。
- 统一的按钮、间距、圆角、字体和颜色规范。
- 提供深色和浅色主题切换。
- 页面适配不同屏幕尺寸。
- 不要使用大量无意义的动画、渐变和装饰。
- 所有可见按钮必须具有真实功能，不要制作无效的交互占位。

## 七、开发顺序

请按以下顺序执行：

1. 检查当前工作目录，确认是否已有项目文件，不要覆盖无关文件。
2. 初始化项目和基础目录结构。
3. 实现页面布局、主题与导航。
4. 实现软件数据模型和首批软件资料。
5. 实现搜索、分类筛选、详情、收藏和已安装状态。
6. 实现环境预设和 JSON 导入导出。
7. 实现本地存储与异常处理。
8. 执行 npm run build，修复所有构建错误。
9. 检查主要交互、空状态、移动端布局和外部链接。
10. 配置 GitHub Pages 的自动部署工作流。

不要在第一阶段实现图片节点编辑器、自动下载器、自动安装器、后端或用户登录。
